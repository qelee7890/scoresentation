### Test infrastructure decision (zero new devDependencies)

- **node:test** (Node built-in) → pure-JS modules `main/canonical-doc.js`, `main/ledger.js`. These MUST NOT import better-sqlite3 / `db.js` (ABI isolation — the native binary is built for Electron and fails under plain `node`).
- **Python `unittest`** (stdlib; `pytest` is NOT present, so not used) → all Python tools under `tools/tests/`. Interpreter resolution on Windows: use the `py -3` launcher (`python`/`python3` are absent from the Git Bash PATH though the project already invokes Python via `npm run server`).
- **Electron smoke gate** (extend the `check-native-abi.cjs` pattern; `electron tools/check-*.cjs`, non-zero exit on failure) → DB integration requiring better-sqlite3: v3 schema/migration (T-003), overlay disposal (T-007), existing-invariant characterization (T-001).
- **Cross-language golden vectors** (`test/fixtures/canonical-golden/*.json`) → asserted by BOTH node:test and Python unittest to guarantee contentHash parity (T-009).
- `package.json` scripts (T-010): `test` = `node --test test/`, `test:py` = `py -3 -m unittest discover -s tools/tests`, `test:electron` = the smoke-gate cjs scripts. Coverage via `node --test --experimental-test-coverage` (pure modules) + Python `unittest` (tools). **Coverage scope note:** better-sqlite3 glue in `main/db.js` is exercised only by Electron smoke gates (pass/fail), not standard line-coverage — the 85% target is measured over pure-JS modules + Python tools.

### Operational discipline (invariant, every task)

Python `sqlite3` only for DB scripts + `PRAGMA wal_checkpoint(TRUNCATE)` after writes; baseline `data/scoresentation.db` read-only at runtime; self-verifying publish chain / ABI guard / WAL packaging filter unchanged. Destructive user-overlay work (T-007) is backup-first and gated behind explicit user approval before any run against real `[U]` data.
